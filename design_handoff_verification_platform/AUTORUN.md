# التشغيل الكامل — رسالة واحدة تجعل كلود كود ينفّذ المنصة كلها

الفكرة: لا توزّع المهام يدوياً. أعطِ كلود كود **عقد عمل** يجبره على التخطيط، ثم التنفيذ شاشة بشاشة، ثم **التحقق آلياً** من نفسه بعد كل شاشة، وعدم المتابعة قبل أن يمر الفحص.

## قبل الرسالة (مرة واحدة، دقيقتان)

```bash
unzip design_handoff_verification_platform.zip -d .
cp design_handoff_verification_platform/CLAUDE.md ./CLAUDE.md
mkdir -p src/styles verify
cp design_handoff_verification_platform/design-system/styles.css src/styles/organic.css
cp design_handoff_verification_platform/verify/check-design.mjs verify/
cp design_handoff_verification_platform/verify/shoot.mjs verify/
```

## الرسالة (الصقها كما هي، ثم اتركه يعمل)

```
أنت تنفّذ منصة تحقق KYB/KYC كاملة من حزمة تصميم جاهزة. اعمل بشكل مستقل ولا تسألني
إلا عند قرار لا يمكن استنتاجه من الحزمة.

المصادر الملزمة — اقرأها كلها قبل أي كود:
- CLAUDE.md
- design_handoff_verification_platform/README.md  (المواصفات الحرفية لكل شاشة)
- design_handoff_verification_platform/screens/*.png  (المرجع البصري)
- src/styles/organic.css  (التوكنات — المصدر الوحيد لكل قيمة)

العقد:
1. لا يُكتب أي لون أو مسافة أو نصف قطر أو ظل بقيمة مباشرة. كل شيء var(--*).
2. العناوين والأزرار Baloo Bhaijaan 2 / النص IBM Plex Sans Arabic. لا Inter ولا Roboto.
3. dir="rtl" على التطبيق، رؤوس الجداول محاذاة يميناً، الآيبان direction:ltr.
4. الأيقونات Lucide بسماكة 2.75 فقط.
5. لكل عنصر تفاعلي hover و:active و:focus-visible بحلقة الأكسنت.
6. لا ذكر لأي مزوّد بيانات خارجي، ولا أي حقل لمفاتيح API خاصة بالمشترك.
7. النصوص العربية في المواصفات هي النص المعتمد — لا تُعِد صياغتها.
8. لوحة السوبر أدمن بالوضع الداكن المحدّد في المواصفات.

الخطة التي تنفّذها بالترتيب، وتحدّث بعد كل مرحلة ملف PROGRESS.md:
المرحلة 0: اكتب PLAN.md فيه المكوّنات والمسارات وشكل البيانات المشتق من المواصفات. توقّف وأرِني.
المرحلة 1: src/components/ui — Button, Tag, Input, Field, Radio, Segmented, Card, Table, Dialog
          مطابقة لفئات organic.css. لا شاشات في هذه المرحلة.
المرحلة 2: القشرة والتنقل — بورتال المشترك (5 أقسام) ولوحة أدمن منفصلة (6 أقسام) كما في شاشة 00.
المرحلة 3: شاشة 03 ملف العميل.
المرحلة 4: شاشة 02 طلب التحقق.
المرحلة 5: شاشة 01 اللوحة الرئيسية.
المرحلة 6: شاشة 04 قائمة العملاء.
المرحلة 7: شاشة 05 الأسعار وإعدادات التحقق.
المرحلة 8: شاشة 06 المشتركون والأرصدة.

بعد كل مرحلة من 2 إلى 8، وقبل الانتقال للتي بعدها، نفّذ بنفسك:
  node verify/check-design.mjs
  وأصلح كل ما يُبلّغ عنه حتى يخرج بصفر أخطاء.
  ثم node verify/shoot.mjs  (يصوّر الشاشة بعرض 1440)
  وقارن صورتك بـ design_handoff_verification_platform/screens/<نفس الرقم>.png
  واذكر في PROGRESS.md كل فرق وجدته وكيف أصلحته.
  ثم مرّ على «قائمة الفحص النهائية» في آخر README.md وأجب على كل بند بنعم/لا.
لا تعلن اكتمال مرحلة وفيها بند «لا».

استخدم بيانات وهمية من المواصفات نفسها (mock layer في src/mocks) حتى يعمل كل شيء بصرياً
بدون backend. اجعل الاستدعاءات تمر عبر src/api/ حتى يسهل ربطها لاحقاً.

ابدأ بالمرحلة 0 الآن.
```

## أثناء العمل: ما تقوله فقط

- إن أنتج شيئاً مختلفاً: **«قارن مع `screens/0X-*.png` واذكر الفروق ثم أصلحها»** — لا تصف الفرق أنت، اجعله هو يكتشفه.
- إن بدأ يبتكر أزراراً أو ألواناً: **«نفّذ `node verify/check-design.mjs` وأصلح مخرجاته»**.
- إن توقّف في منتصف الخطة: **«أكمل من المرحلة التالية في PROGRESS.md»**.

## لماذا يضمن هذا التطابق

ثلاث طبقات تمنع الانحراف، ولا تعتمد على انتباهك:

1. **`CLAUDE.md` في الجذر** — يُقرأ في كل جلسة، فلا تُنسى القواعد بعد ساعة عمل.
2. **`verify/check-design.mjs`** — يرفض آلياً أي لون مباشر، أي خط ممنوع، أي `px` في الأنصاف، أي عنصر تفاعلي بلا `focus-visible`. الانحراف يصبح خطأ يفشل، لا ملاحظة تُهمل.
3. **`verify/shoot.mjs` + صور `screens/`** — مقارنة بصرية إلزامية بعد كل شاشة، مسجّلة في `PROGRESS.md`.

أضف الفحص إلى الـ CI وإلى `pre-commit` حتى لا يعود التصميم للانحراف بعد انتهاء كلود:

```jsonc
// package.json
"scripts": {
  "design:check": "node verify/check-design.mjs",
  "design:shots": "node verify/shoot.mjs"
}
```
